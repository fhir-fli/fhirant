## 2. Records lost, or clinical answers wrong

**R1. 🔴 No backup made by the CLI or the app can be restored. CONFIRMED.**

> ✅ **FIXED 2026-09-17** (`2e867b8` and the two commits after it). `copyEncrypted` writes one format, SQLCipher 4, from any store; `restoreEncrypted` finds the file's `legacy` setting by opening it (4, then 0), so backups written before the fix by either kind of store restore. `store_cipher.dart` is the one place the store's cipher configuration is written; the CLI and the app call it. **The end-to-end check found a second defect (R1b):** `$restore` over a real socket answered 500 before opening the file, because `request.read().pipe(IOSink)` throws a TypeError when the body is a `Stream<Uint8List>`, which it is behind `dart:io` and never is in an in-process handler test. Fixed, with the first test in the suite that goes through a socket. Two running CLI servers, backup from one, restore into the other: 400 on the wrong passphrase, 200 and the Patient readable on the right one. Evidence: `packages/fhirant_server/tool/review_2026-09-17/fix_r1/`. D1's probe can now run.
`bin/server.dart:126` and `database_service.dart:67` open the store with `PRAGMA legacy = 4`. `copyEncrypted` attaches the backup on that connection, so the file is written with the legacy-4 parameters. `restoreEncrypted` (`fhirant_db.dart:503-505`, and the upgrade open at `:522-525`) opens it with `cipher` and `key` only; SQLite answers "file is not a database" and the operator is told the passphrase is wrong.

| step | result |
|---|---|
| backup from a store opened as production opens it | written, 131,072 bytes |
| raw open the way `restoreEncrypted` does (no `legacy`) | **fails: file is not a database** |
| raw open with `PRAGMA legacy = 4` added | opens, `user_version=23`, 1 resource |
| `restoreEncrypted` into the same store, and into a fresh production-configured store | **BackupUnreadable**, both |
| the same round trip from a plain in-memory store (what every backup test runs) | restored 1 |

The backups are not damaged: they open with `legacy = 4`. The restore path is what fails, for every backup a real install has made. Every backup test builds its store with `NativeDatabase.memory()` and no cipher pragmas, which is why none saw it.
Fix: one function that applies the cipher configuration (`cipher`, `legacy`, `key`), used by the CLI, the app, the ATTACH in `copyEncrypted` and both opens in `restoreEncrypted`; a backup test whose source store is opened exactly as `bin/server.dart` opens it; restore also tries `legacy = 4` for files written before the fix.

**F1. 🔴 The forecast swallows a failed read of the history. CONFIRMED.**

> ✅ **FIXED 2026-09-17.** `_searchForPatient` no longer catches; a failed Immunization, Condition or AllergyIntolerance read is a 500 with an OperationOutcome and no recommendation, on both request shapes (6 tests, 0 of 6 before). Checked at the handler with a store that throws; not induced through a running CLI, which has no fault to inject. Evidence: `packages/fhirant_server/tool/review_2026-09-17/fix_f1/`.
`forecast_handler.dart:212-227`, `_searchForPatient`: `catch (_) { return []; }`. With every search throwing, `$immds-forecast` answered **200 with an ImmunizationRecommendation** (56,712 bytes). A failed Immunization read becomes "no doses given", so every dose is due; a failed Condition or AllergyIntolerance read drops the contraindications. Nothing in the response says so. Fix: let it throw; 5xx.

**S3. 🔴 The `spec` tag is client-writable, and it decides what a backup contains. CONFIRMED.**
`$backup` and system `$export` leave out every resource whose `meta.tag` carries `http://fhirant.fhir-fli.dev/CodeSystem/tags|spec` (`spec_loader.dart:27-36`, `copyEncrypted(withoutTag:)`, `BackupService.bundle`). A clinician PUT a Patient carrying that tag; the backup restored **1 of 2 patients**. The same shape as the DELETED-tag tombstone of 2026-09-08 row 36: a server decision keyed on a field a client writes. Fix: a server-owned column (or refuse/strip the tag on any write that is not the specification load). This does not reopen where the specification lives (decided 2026-09-08: in `resources`); it is about what marks it.

**Q1. 🔴 Dates with no zone are indexed in the device's local zone. CONFIRMED.**
`fhir_date.dart:100-110`. Indexed under `TZ=America/New_York`, `Patient?birthdate=1990-01-15` matched 1; the same file searched under `TZ=Asia/Tokyo` matched **0** (`eq` is containment, and the stored day no longer sits inside the searched day). A phone that travels, or whose zone setting changes, silently loses equality matches on every zone-less date: every `birthDate`, every date-only `onset`, `effective`, `issued`. R4B search.html 3.1.1.4.7 asks for the server's local zone "Where both search parameters and resource element date times do not have time zones"; a server whose zone moves cannot do that with stored instants. Fix: index and search zone-less values in one fixed zone (UTC) on both sides, so the comparison is zone-independent; the rebuild re-extracts every row.

**Q2. 🔴 Searches during `$reindex` read a half-built index. CONFIRMED.**
`rebuildSearchIndex` (`fhir_db.dart:493-582`) drops the nine tables, refills them 500 resources at a time, and creates the indexes last, none of it in one transaction. With the store on its own isolate (the app's configuration), `gender=female` over 6,000 Patients polled during a 2.5 s rebuild gave **14 different answers from -1 (SQL error: table missing) to 6,000**. `reindex_handler.dart:20` puts the 929k-resource rebuild at about 1,000 s. With the store on the server's isolate (the CLI) the same rebuild instead holds the whole server: my first probe could not get one poll in. Fix: build into shadow tables and swap them in one transaction; or answer 503 to searches while it runs.

**T1. 🔴 "This server does not hold that CodeSystem" is answered as "no such code". CONFIRMED.**
A ValueSet including all of `http://loinc.org`: `$expand` **200, total 0**; `$validate-code` of LOINC 8867-4 **200, result=false**; `Observation?code:in=` **0**; `code:not-in=` **every Observation**. `terminology_handler.dart:412-415, 716-726` and `fhir_dao.dart:4282-4296` skip a CodeSystem that is not found. The 2026-09-06 rule (finding 24: refuse a compose the server cannot evaluate) was applied to `filter` and `valueSet` and not to this. Also unhandled: a CodeSystem present with `content` other than `complete`. Fix: 422 / 400 `not-supported`, as finding 24 does.

**T2. 🟠 `$validate-code` does not apply `compose.exclude`. CONFIRMED.**
Include all of a CodeSystem, exclude code `a`: `$expand` lists `[b]`, `$validate-code` of `a` answers **true**. `terminology_handler.dart:697-726` returns on the first include that matches; the comment at `:729` says the excludes need no check. REVIEW-2026-09-08 line 30 lists this as "Refuted by reading". It was read wrong; the probe is the correction.

**D1. 🟠 Restore over a newer local version regresses the resource and then overwrites its history. BY READING** (the probe could not run until R1 is fixed).
`restoreEncrypted` does `INSERT OR REPLACE INTO resources` from the backup (`fhirant_db.dart:575`): a local v3 is replaced by the backup's v1, and v3 is not moved to history. The next saves count v2, v3 again, and `saveResource` upserts history by `(type, id, version)` (`fhir_dao.dart:247`), replacing the local v2 and v3 rows.

## 3. Security, with authentication on

**A1. 🔴 patient/ scopes with no patient context are unconfined at the root. CONFIRMED.**
`Principal.compartmentFor` returns null (no confinement) when the token has no `patient` claim (`request_authorization.dart:85-86`). `authorizeRequest` refuses such a token only on typed paths (`:175-180`). `GET /?_type=Patient` with scopes `patient/*.rs` and no patient: **200, total=2**, both patients. `/auth/register` lets an administrator create that account (scopes `patient/*.rs`, no `patient`), and `/auth/login` issues the token as the account has it. Fix: a patient-context scope with no patient context fails closed in `compartmentFor` and at login.

**A2. 🔴 The audit trail is writable by the people it records. CONFIRMED.**
A clinician (`user/*.cruds`): `PUT /AuditEvent/{id}` with another agent and outcome **200**, `DELETE` **204**. Fix: AuditEvent is append-only to everyone but the server; refuse PUT, PATCH, DELETE and client POST in `authorizeRequest` and in Bundle entries.

**A3. 🟠 Account lockout ends live sessions and can be held indefinitely by anyone. CONFIRMED.**
The middleware refuses a valid token while the account is locked (`auth_middleware.dart:110-113`), and five wrong passwords lock any known username (10 credential requests a minute are allowed per address). Before: 200. After five anonymous wrong logins: **401** on the victim's valid token. Repeated every 15 minutes it keeps the only administrator out. Fix: a lock blocks password login; it does not revoke sessions.

**A4. 🟠 OAuth: any `client_id`, any `redirect_uri`, first use wins. CONFIRMED.**
An unregistered `growth-chart` with `redirect_uri=https://evil.example/cb` and the user's password: **302 to evil.example with the code**; the attacker chose the PKCE challenge, so the attacker holds the verifier. The consent page names the `client_id` the attacker typed and not the redirect host. Trust-on-first-use (`authorize_handler.dart:432-435`) also lets any account holder pin a well-known client id to their own URL. Fix: clients are registered by an administrator; an unregistered client is refused, or limited to loopback and private-use schemes; show the redirect host.
Also CONFIRMED: `Uri.replace(queryParameters:)` drops the redirect URI's own query (`?keep=1` was lost); RFC 6749 3.1.2 requires it kept.

**A5. 🟠 HEAD is never scope-checked. CONFIRMED.**
`methodToPermission` has no case for HEAD (`smart_scopes.dart:192-231`), so the middleware checks nothing, and shelf_router serves HEAD from every GET route. Token `user/Observation.rs`: `GET /Patient/a` **403**, `HEAD /Patient/a` **200** (with ETag and Last-Modified). Compartment checks inside handlers still run; the type scope does not.

**A6. 🟠 A SearchParameter can be deleted without system authority. CONFIRMED.**
`DELETE /SearchParameter/id` as a clinician: 403. `DELETE /SearchParameter?code=…`: **204** (then 410 on read). A Bundle `DELETE` entry: **204**. The check lives in `deleteResourceHandler` only.

**A7. 🟠 REST PATCH skips the Subscription service. CONFIRMED.**
`patchResourceHandler` takes no `SubscriptionService` (`fhirant_server.dart:552-556`). A Subscription the server had set to `error` (unsupported channel) was PATCHed to `active` and stored **active**: the client decides its own status. A PATCH of any other resource notifies no subscriber. The Bundle PATCH path does both. `$meta-add` and `$meta-delete` also notify nothing.

**A8. 🟠 Bulk export writes the record to disk in plaintext. CONFIRMED.**
After `$export`, `Patient.ndjson` under the export directory contained the patient's name, readable, and stays 24 h (`kExportRetention`). The database beside it is encrypted. In the app the directory is under Documents (`database_service.dart:78-85`), which iOS includes in device backups. `FhirAntDb.exportJson` already streams from the store: `$export-file` can stream from the store and write no file; the manifest needs only counts.

**A9. 🟠 Client-supplied programs run on the server's isolate with no deadline. CONFIRMED (cost measured).**
`$fhirpath`, `$cql`, `Library/$evaluate`, `$transform`. A 293-character FHIRPath expression (six nested `select`s over ten literals) held the handler **1,002 ms**; each further 48 characters multiplies that by ten (3, 4, 5, 6 levels: 63, 75, 120, 1,002 ms; the tenfold step is measured from 5 to 6, extrapolated beyond). While it runs, nothing else is served. Fix: evaluate in a worker isolate with a deadline and kill it.

**A10. 🟠 No request body limit. CONFIRMED.**
A 20 MB Patient was accepted: **201**. Every write route is `request.readAsString()`. On a phone this is memory.

**A11. 🟠 Password hashing blocks the server and is below current guidance. MEASURED.**
One login is **290-337 ms** of synchronous PBKDF2 on the server isolate on this desktop (phone: unmeasured). OWASP Password Storage Cheat Sheet (raw markdown read 2026-09-17, section "PBKDF2", verbatim): "PBKDF2-HMAC-SHA256: 600,000 iterations (recommended)", and its summary: "Use Argon2id with a minimum configuration of 19 MiB of memory, an iteration count of 2, and 1 degree of parallelism." fhirant uses 120,000 (`password_hasher.dart:25`), in a hand-written loop that builds a new HMAC per round; `pointycastle`, already a dependency, has Argon2 and PBKDF2. Run it in `Isolate.run`.

**A12. 🟡 Login tells accounts apart. CONFIRMED.** Deactivated account **403**, unknown user **401**, locked 423, all before the password is checked; the deactivated path also skips the decoy hash (`credential_check.dart:72`).

**A13. 🟡 Existence oracle. CONFIRMED.** For a patient token, another patient's Observation is **403**, an absent one **404**, a deleted one 410.

**A14. 🟡 No account management.** No route changes a password, deactivates an account (`deactivateUser` exists in the store, nothing calls it), or changes role or scopes; the app can create the first administrator and nothing else. A leaked password can only be fixed in the database. BY READING.

**A15. 🟡 First-user bootstrap is a race on the CLI and Docker.** With authentication on and no users, the first `POST /auth/register` from anyone on the network becomes the administrator. The app provisions its administrator locally; the CLI has no equivalent (an environment variable, or a one-time token printed at start). BY READING.

**A16. 🟡 Smaller, BY READING.** Refresh rotation has no reuse detection. The authorization-code `used` check and the mark are two statements (`refresh_handler.dart:109-181`), so two concurrent exchanges both succeed. Token responses carry no `Cache-Control: no-store`. The login page has no frame or content-security headers. `Pkce` still accepts `plain`. Websocket `bind` accepts any id, any number of ids per socket, and does not check that the Subscription exists. The backup envelope's `kdf.iterations` is read from the file with no ceiling. Compartment membership ignores `reference_base_url` where `_include` checks it. Failed logins are audited as `anonymous` with no attempted username. `AuditQueue` ignores `saveResources` returning false, so a failed batch is lost without a line in the log. AuditEvents have no retention; every read writes one.

## 4. Searching, SQL, and Dart against SQL

**Assessment.** The SQL is the strongest part of the codebase. Covering indexes per value column, keyset paging, ranges instead of LIKE, sentinel bounds instead of NULL, `+column` to steer the planner, partial indexes for contained rows: each is measured on the 929k MIMIC store and the measurement is written beside the code. Parameters are bound everywhere user text reaches SQL; the string-built SQL (`_historyCompartmentSql`, the PRAGMA key, table names in backup) takes only generated constants or escaped literals. I found no injection.

The structural weakness is that **search is implemented twice.** `_pagedIds` (SQL) handles nearly everything; `_matchingIds` and the `_search*Parameter` functions (`fhir_dao.dart:2900-3066, 3708-5447`, about 1,600 lines) are an older Dart set-arithmetic engine still reached for `:of-type`, `_id` lists over 500, `_filter` sets over 500, and an unsortable `_sort`, and then it evaluates every other parameter of that request too. It reads whole rows including the JSON to collect ids (`:3054`, `:3771`, `:3926`, `:4009`, `:4569`, `:4714`), runs one search per reference row for a chain (`:5233-5250`), and ignores `referenceParam` in `_has` (`:5431-5437`). For the one bad value I tried the two paths agreed (both 400). Recommendation: make the general path compose the same `_conditionFor` conditions (one `SELECT id` per parameter, intersected), keep Dart only for the `:of-type` post-filter, and delete the per-type functions.

**Q3. 🟠 Modifiers the specification does not give a type are accepted and answered as something else. CONFIRMED.**
R4B search.html 3.1.1.4.4 (section printed whole 2026-09-17, verbatim): "For string: :exact … or :contains", "For reference: :[type] where [type] is the name of a type of resource, :identifier, and, for some parameters, :above and :below", and "Server SHALL reject any search request that contains is suffixed by a modifier that the server does not support for that parameter". `modifiersByType` (`search_query_key.dart:250-258`) gives string `text` and reference a literal `type`. `Patient?name:text=tex` **200 total 1** (answered as starts-with); `Observation?subject:type=Patient` **200 total 0**.
**Q4. 🟡 `:missing=maybe` is read as false: 200. CONFIRMED.** Only `true` and `false` are values.
**Q5. 🟡 `subject:identifier=|42` ignores the no-system form: 2 matches, 1 expected. CONFIRMED.** The token rule for a leading pipe (`_tokenCondition`) is not applied to `:identifier`.
**Q6. 🟠 A Bundle GET entry ignores `_has` (and `_include`, `_summary`, `_elements`, `_filter`). CONFIRMED.** REST total 1, the same search as a batch entry total **2**. `_entrySearch` (`bundle_handler.dart:1013`) passes `searchParams`, `count`, `offset`, `sort` and nothing else.
**Q7. 🟡 A Bundle entry URL with three segments is processed as its first two. CONFIRMED.** `GET Patient/a/_history` inside a batch returned **the Patient**. Also true of `Patient/a/$everything`.
**Q8. 🟡 `_contained=true|both` is refused as "this server does not index contained resources"** (`resource_handler.dart:485-490`, `search_parser.dart:113-118`, dated 2026-09-02). Contained resources have been indexed under `#Type` since fhir_db schema 7. BY READING.
**Q9. 🟡 `If-None-Exist` searches have no `count`** (REST `resource_handler.dart:1203`, Bundle `:622`): every match is hydrated to learn whether there are 0, 1 or 2. `_typeFilter` in `$export` calls `search` where `searchIds` exists (`export_handler.dart:629, 723`). BY READING.

**SQLite configuration. MEASURED** (`store_probe.tsv` F4, `store_probe2.tsv` WAL).
The build: 3.53.4, `TEMP_STORE=2` (sort spills stay in memory, which is what an encrypted store needs), no `STAT4`. A file store opens with `journal_mode=delete synchronous=2 foreign_keys=0 busy_timeout=0`; nothing sets a PRAGMA but the cipher. 200 single-resource commits on this disk:

| journal_mode / synchronous | per commit |
|---|---|
| delete / FULL (today) | **23.8 ms** |
| wal / FULL | 8.5 ms |
| wal / NORMAL | 0.5 ms |

WAL with FULL keeps today's durability at about a third of the cost. WAL with NORMAL can lose the last commits on power loss (never corrupts); that choice is a clinical one. The probe-size planning in `_pagedIds` exists because the build has no STAT4; whether the `sqlite3` build hook can define `SQLITE_ENABLE_STAT4` is unknown, I did not look.

## 7. Structure and coding

**Assessment.** The package split is right (app → server → db → logging; secure storage beside it), the store is model-independent with a thin binding, handlers are functions over a `FhirAntDb`, and authorization was pulled into one `Principal` on 2026-09-09. Comments record the measurement or the specification sentence behind a choice, which is why this review could check them. What follows is what the structure still costs.

- **ST1. Response helpers are copied into every handler.** 22 private `_errorResponse` / `_validationErrorResponse` / `_operationOutcome` / `_outcome` / `_baseUrl` functions and 28 hand-built OperationOutcome maps across `handlers/`, beside a shared `operation_outcomes.dart` that has two functions. They already disagree: some answer `application/json`, some `application/fhir+json`, some no content type; some build the FHIR class and some a Map.
- **ST2. Authorization is still spread across three layers.** The middleware checks the first path segment; each handler then re-checks the type it really returns (`compartment_handler`, `export_handler`, `document_handler`, `cql_handler`, system search, history), each in its own words. A5, A6 and A7 are all "one path forgot". A route table that declares, per route, the permission, the type it returns and whether it is compartment-confined would make the omission impossible to write.

With one-type scopes (`security_probes.tsv`): `_include`, `_revinclude`,

## Findings

**1. 🟠 In the Docker image, every bulk export fails.** The export directory
defaults to `data/export` relative to the working directory
(`fhirant_server.dart:62`; the CLI never sets it). The image's working
directory is `/root` (`drwx------ root`), and the process runs as user 1000.
Every `$export` job fails; the poll answers 500 "Export failed".
A/B, one variable (`docker_probe.txt`): the same image with `-w /data`
answers 200 and the file is at `/data/data/export/…`. `test_docker.sh`
never runs an export, so CI is green. The same default makes a CLI
server's export files depend on the directory it was started from.
Change: the CLI passes an export directory under `--db-path`. One line in
`bin/server.dart`, and an export case in `test_docker.sh`.

> ✅ PR #38: the CLI passes `<db-path>/export`; `test_docker.sh` gained an export case, which failed (500) against the old code and passes now.

**2. 🟠 When every search parameter is ignored, the self link says they were
applied.** R4B search.html §3.1.1.6: "the server SHALL return the
parameters that were actually used to process the search … encoded in the
self link". `Observation?patiet=Patient/pat1` (a typo) returns every
Observation, and the self link reads `?patiet=Patient/pat1`. The same for
`_sort=not-a-param` alone (`search_probes.tsv`). With one known parameter
present the unknown one is correctly dropped. Cause: `search_links.dart`,
`requested.replace(queryParameters: params.isEmpty ? null : params)`. In
Dart, `Uri.replace` keeps the original query when `queryParameters` is
null. A client that checks the self link, as the spec tells it to, shows
every patient's results as one patient's. Change: build the URL with an
empty query when nothing was used. One line and a test.

> ✅ PR #39: the URL is rebuilt with no query when nothing was used; the two all-ignored cases failed before.

**3. 🟠 Conditional references in a transaction are stored as written.**
R4B http.html §3.1.0.11.2: "When processing transactions, servers SHALL:
check all references for search URIs … if there are no matches, or
multiple matches, the transaction fails … if there is a single match, the
server replaces the search URI". An Observation posted in a transaction with
`subject: Patient?_id=pat1` is stored with exactly that string. It is not
in pat1's `$everything`, and no match or several matches do not fail
(`http_followups.tsv`). This is how interface engines send results.
Change: resolve search-URI references in the transaction processor before
the entries are processed; fail on 0 or more than 1.

> ✅ PR #41: POST and PUT entries resolve search-URI references in the caller's own search (403 without search on the type, a patient token's compartment); none or several matches are 412 and roll back. 5 of 7 tests failed before.

**4. 🟠 JSON Patch leaves the narrative saying the old value.** R4B http.html
§3.1.0.6: "The server SHALL ensure that the narrative in a resource is not
clinically unsafe after the PATCH operation is performed." A potassium
Observation with narrative "Potassium 3.0 mmol/L (LOW)" (status
`additional`), patched to 6.5, reads back with value 6.5 and the same
narrative. The spec offers four remedies. The smallest is to refuse a patch
when the narrative status is not `generated`, or to drop the narrative.
Which one is a choice; refusing is the only one that loses nothing.

> ✅ PR #42: a patch that writes `/text`, or changes only `text`/`meta`, stands; otherwise a `generated` narrative is removed, an `empty` one kept, and `additional`/`extensions` refuses 422. 4 of 8 tests failed before.

**5. 🟠 Two sessions minted in the same second are the same token.** The
JWTs carry no `jti` or nonce (`jwt_service.dart`). Two logins of one
account back to back came out byte-identical on the first try (the probe
stops at the first identical pair; `token_identity_probe.tsv`).
Measured effects: device 1 logging out ends device 2's session (401), and a
refresh in the same second as login returns the same refresh token it has
just revoked, so the next refresh is 401 "revoked". Change: a random `jti`
(RFC 7519 §4.1.7) in every access and refresh token.

> ✅ PR #40: every access and refresh token carries a 128-bit random `jti`; both tests (identical strings; the other session's 401) failed before.

**6. 🟠 Chained search, `_has` and conditional create reach types the
scopes do not cover.** R4B security.html §6.1.0.5.1: "A security
implementation must consider whether a client has the permission to access
the resource being searched on, as well as the chained resource(s)". With
`user/Observation.rs` only, `Observation?subject:Patient.family=X`
answers 2: a patient named X exists, and these are their results. With
`user/Patient.rs` only, `Patient?_has:Observation:subject:code=…` answers
which patients have that result. `If-None-Exist` with a chain answers 412
or 201, which is the same oracle (`security_probes.tsv`). Change: refuse a
chain, `_has` or conditional criterion whose target type the caller cannot
search, the way `_include` already does.

> ✅ PR #43: `auth/search_reach.dart` works out every type the criteria read (typed and untyped chains, every hop; `_has`, nested; chains in `_filter`), and type, system and compartment search, conditional create/update/delete (REST and Bundle), transaction conditional references and export `_typeFilter` refuse 403; Subscription criteria are kept in `error`. 13 of 17 tests failed before.

**7. 🟠 (cicada, served by fhirant) A patient with no birth date gets a full
forecast.** `$immds-forecast` for a Patient with no `birthDate` answers
200 with 16 recommendations (`forecast_probe.tsv`). cicada substitutes
1900-01-01 (`patient_for_assessment.dart`, three sites). The CDSi logic
specification 4.6, Table 5-2, gives Gender an assumed value if empty
("Unknown") and gives Date of Birth none. The fix belongs in cicada
(refuse), and then fhirant answers 4xx. cicada has its own suite and rulings,
so this is a cicada work item, not a fhirant change.

> ✅ fhir-fli/cicada #3: a Patient with no birthDate is refused, as a missing Patient is (cicada 1,477 tests, CDC suites unchanged). fhirant PR #60: 422 before the engine runs. The run before #60 shows what the old answer said: "Immune" to measles, mumps and rubella.

**8. 🟡 An invalid required code is stored.** `Observation.status:
"not-a-status"` (required binding) is accepted 201, read back and
searchable; the server's own `$validate` of the stored copy reports the
error. http.html §3.1.0.8: "When the resource syntax or data is incorrect
or invalid … the server returns a 400".

> ✅ PR #44: a code the bound enum does not define is 400 on create, update, patch and every Bundle write. Run over the published R4B examples, the check flags 0 of 3,012 resources (`unknown_codes_census.tsv`). 5 of 6 tests failed before.

**9. 🟡 A malformed `If-Match` turns into an unconditional update.**
`If-Match: garbage` and `If-Match: W/1` update the resource (200); `"1"`
and a list are compared and refused 412. A client that sends a bad header
loses the lost-update protection without knowing.

> ✅ PR #45: an `If-Match` that is neither `*` nor a list of entity tags compares as a version none can equal (RFC 9110 13.1.1, "Otherwise, the condition is false"). A list is still compared by its first tag. 9 of 11 tests failed before.

**10. 🟡 A transaction may touch the same resource twice.** Two PUTs to
`Observation/ov9`, or a DELETE and a PUT of `obs1`, in one transaction are
accepted and the last wins. http.html §3.1.0.11.2: "If any resource
identities … overlap in steps 1-3, then the transaction SHALL fail."

> ✅ PR #46: a second change of one identity fails the transaction 400. The REVIEW-2026-09-06 row 16 test, which itself DELETEd and PUT one id, now shows the same order without an overlap (it fails with DELETE ranked after PUT). 4 of 5 new tests failed before.

**11. 🟡 Any account can bind to another account's websocket subscription.**
Not ruled on in A16.6 ("the only exposure … not ruled on"); now measured:
a second clinician's `bind <id>` of the first one's Subscription answers
`bound` and receives its pings. Pings carry no data, but they say when
the other account's criteria matched.

> ✅ PR #47: a socket binds a STORED Subscription only when its token may read it; an id that is not stored still binds (A16.6). Limit: a `user/*.*` clinician can read every Subscription, so one clinician binding another's is still allowed.

**12. 🟡 `Subscription.channel.header` is readable by every account that can
read Subscriptions.** The spec's own example puts `Authorization: Bearer …`
there. A second clinician's search returned the first Subscription with its
header.

> ✅ PR #48: one response middleware inside the auth check removes `channel.header` for callers without system authority and labels the resource REDACTED. 7 of 9 tests failed before.

**13. 🟡 Provenance is missing from Patient and Group exports.** Bulk Data
export.html: "the server SHALL include all available Provenance resources
whose Provenance.target is a resource in the Patient compartment in a
patient level export request". A Provenance targeting pat1's Observation is
absent from both (`bulk_probes.tsv`).

> ✅ PR #49: every stored Provenance is read once and those with an exported target are added. All 3 tests failed before.

**14. 🟡 A file download that asks for `application/fhir+ndjson` gets 406.**
Bulk Data export.html, File Request: "Accept (optional, defaults to
application/fhir+ndjson)". `contentNegotiationMiddleware` accepts only JSON
types; no Accept, `*/*` or `application/fhir+json` gets the file.

> ✅ PR #52: the three NDJSON spellings are accepted on `$export-file/` only. 3 of 5 tests failed before.

**15. 🟡 A forecast request that names no patient answers 500.** A
`Parameters` body with no `patientId` and no Patient resource reaches
cicada, which throws, and the catch-all answers 500 and logs SEVERE. The
client's input is the fault.

> ✅ PR #53: 400 before the engine (ImmDSForecastOperation 1.0.0: `patient` 1..1). Not changed: the same definition makes `assessmentDate` 1..1, which the plain-JSON form lets default.

**16. 🟡 Responses carrying patient data have no `Cache-Control: no-store`.**
Patient read, search and `$everything` (ASVS 5.0 V14.3.2, L2).

> ✅ PR #54: `noStoreHeaders` on every response to an authenticated request that set no Cache-Control. 5 of 6 tests failed before.

**17. 🟡 Refresh tokens have no absolute lifetime.** Each rotation issues a
token with a fresh 7 days, so a session that refreshes weekly never ends
(ASVS V10.4.8, L2).

> ✅ PR #55: a rotated refresh token keeps the expiry of the one it replaced, and an access token from a refresh ends no later. Both tests failed before.

**18. 🟡 The common-password list has 20 entries.** ASVS V6.2.4 (L1): "at
least, the top 3000 passwords which match the application's password
policy". `qwertyuiopasdfgh`, `1qaz2wsx3edc4rfv` and sixteen `a`s were
accepted. Length 12–128, no composition rules and no truncation all hold.

> ✅ PR #56: 30,407 entries from two SecLists lists (NCSC 100k, Pwdb top 1M; MIT), built by a SHA-256-pinned generator. The existing 12-character test used `abcdefghijkl`, which is on the list; its value changed, not its meaning.

**19. 🟡 The first use of a `redirect_uri` is not checked for form.** RFC 6749
§3.1.2: "The redirection endpoint URI MUST be an absolute URI … MUST NOT
include a fragment component." `javascript:alert(1)`, `…/cb#frag` and
`not a url` were accepted, pinned, and sent the code. Pinning itself is
settled; this is only the form check before it.

> ✅ PR #57: refused (400, no redirect) unless absolute, with no fragment, not javascript/data/vbscript, and http(s) with a host; checked before any pin comparison, so an old bad pin is refused too. 7 of 10 tests failed before.

**20. 🟡 First boot takes 31 s before the server answers anything.** The

> ✅ PR #59: `test_docker.sh` waits up to 120 s per container; HEALTHCHECK start-period 90 s. That run booted in 21 s, inside the old wait as well: the change adds margin.

**21. 🟡 An export's failure cause is not logged.** Finding 1 left only

> ❌ WITHDRAWN 2026-10-18: the cause is logged ("Export job ... failed", `PathAccessException ... Permission denied`, measured with the pre-fix binary). The Docker log filter used for the finding was wrong (`\$` in double quotes became a regex anchor, and `tail -4` showed only poll lines).

## ASVS walk

`asvs_walk.tsv` gives every one of the 345 requirements a verdict and its
evidence: N/A 61 (no cookies, MFA, WebRTC, GraphQL, federation or public-key
crypto), DOC 31 (documentation requirements, not probed), NOTPROBED 54
(applies, not measured here; each says why), and the rest PASS or FINDING

Scope: every hand-written Dart file under `lib/` and `bin/` of the five

until the reading and probing were done. 103 files, 26,081 lines:
fhirant_server 80 (bin 1, lib 79), fhirant_db 5, fhirant_logging 1,

finding turned on them: `fhir_db` 0.15.0 `search`/`_pagedIds`/`_idsIn`,
`shelf_rate_limiter` 1.0.1 `MemStorage`, `fhir_path` 0.15.0
`FhirWorkerContext.getResourceNames`, `fhir_r4_mapping` and

the websocket case), results one line per case in `results.tsv`

"no finding" rows are listed too. Nothing was changed in the code.

## Findings

**1. 🔴 A deactivated or demoted administrator's token still creates
administrators.** `auth_middleware.dart:69-86`: on a public path
(`auth/*`, `.well-known/*`, `metadata`, `health`, `favicon.ico`) a token is
only signature-verified and revocation-checked, then injected as
`auth_user`; the account is not re-read, so `active` and the token
generation (A14) are not checked there. `register_handler.dart:850-851`
then trusts `auth_user['role'] == 'admin'`. Probe P1: admin A's token after
A is deactivated (and its generation moved on, as `setActiveHandler` does)
is 401 on `GET /Patient` and **201 on `POST /auth/register` with
`role: admin`**; the new row exists with role `admin`. The same after A is
demoted to readonly. Deactivating a compromised administrator is the
response to a leaked credential, and it does not hold: the holder mints a
fresh administrator with its own password and reads every record.
Change: in the public-path branch, re-read the account and apply the same
`active` and `tokenPredatesAccount` checks as the main branch (or inject
nothing when either fails). One function, three tests (deactivated,
demoted, control).

**2. 🟠 `FHIRANT_ENCRYPTION_KEY=` (set but empty) opens the store in the
clear, silently.** `bin/server.dart:51-52` reads the variable with `??`,
so an empty string passes; `encryptionKeyRefusal('')` returns null (P7
row 1) because `''` is not in `publicKeys`; `applyStoreCipher(raw, '')`
runs `PRAGMA key = ''`, which sqlite3mc treats as no key. P7: the file
written under `''` starts with `SQLite format 3` and the Patient's family
name is readable in the file; under a real key neither. The compose file
is safe (`${VAR:?}` fails on empty), but a systemd unit, a shell `export
FHIRANT_ENCRYPTION_KEY` with no value, or `KEY=$UNSET` in a script all
produce exactly this, and the server logs nothing. Change: treat an empty
value as unset in `bin/server.dart` (and refuse an empty key in
`applyStoreCipher`, which the app also goes through).

**3. 🟠 A patient-confined token learns when another patient's records
are written, through a websocket Subscription.** `subscription_service.dart
matches()` runs the criteria against the store with no compartment, and
`_deliver` pings every bound socket. A token `patient/*.rs
user/Subscription.*` (the shape of an ordinary SMART patient app with a
subscription scope; `patient/*.*` alone is refused at create, P11a) creates
`Observation?subject=Patient/pat2&code=http://loinc.org|718-7` as `active`
(P11 row 1), binds (row 2), and receives `ping <id>` when an administrator
writes pat2's 718-7 Observation (row 3), while its own search for pat2's
Observations answers `total=0` (row 4). The ping carries no payload, but
the criteria are the client's: existence of a named patient, a named lab, a
name match, are each one subscription away. Change: store the creating
principal's compartment on the Subscription (an extension under our
namespace, as the failure counter is) and run `matches()` inside it; or
refuse a Subscription whose criteria type the principal's search is
confined on. The bind-ownership gap REVIEW_DECISIONS leaves unruled is
adjacent, not the same.

**4. 🟠 The credential rate limit is bypassed with a doubled slash.**
`fhirant_server.dart:806-812` `_onPaths` matches `request.url.path` against
`auth/login` exactly; the router matches `//auth/login` too. P2: with the
credential limit at 2, `POST /auth/login` ×4 answers 401,401,429,429;
`POST //auth/login` ×4 answers 401,401,401,401 (the handler ran every
time). The trailing-slash, double-slash-inside and encoded variants are
404 (router), so only the leading double slash gets through. What remains
is the general limit (600 a minute) and the five-attempt lockout per
account; what is lost is the 10-a-minute brute-force bound per address
across accounts. Change: normalise the path once (collapse repeated
slashes) in the trusted-ip middleware, so limiter, audit and router all see
one spelling; or match the credential set on the router's normalised path.

**5. 🟡 `every_route_refuses_a_garbled_body_test` logs itself out at its
fifth route and then measures 401 on the other 42.** The route list is
read from the source in registration order; `POST /auth/logout` with the
admin token revokes it, and every later row is 401 (debug run,
`garbled_test_statuses.txt`: 42 of 47 routes answer 401 at both content
types). The test asserted nothing about any data route since it was
written. Change: skip `/auth/logout` and `/auth/revoke`, or mint a fresh
token per route; then assert at least one 4xx that is not 401 per route.

**6. 🟡 `PUT /[type]/[id]` with a garbled body is a 500.** Hidden by 5.
`resource_handler.dart:1329-1330` parses inside the one catch. P3: PUT
garbled → 500 `exception`; an invalid element value → 500; `POST /Patient`
and `PUT /Patient?identifier=x` garbled → 400 (both parse outside their
catch, ST7). Change: parse outside the catch, as the POST and conditional
PUT already do.

**7. 🟡 Update-as-create under a patient scope: REST refuses, a Bundle
entry creates.** `putResourceHandler` checks `isInPatientCompartment` on a
resource that does not exist yet (count 0 → 403); the Bundle PUT
(`bundle_handler.dart:833-842`) treats `StoredAbsent` as a create and
checks only the body. P4: `PUT /Observation/new1` with the patient's own
Observation → 403; the same as a transaction entry → 200 with the
Observation stored. One rule for both; the Bundle's (check the body) is the
one that matches R4B "Update as Create", and the CapabilityStatement says
`updateCreate: true`.

**8. 🟡 JSON Patch `test` compares encoded strings.** `json_patch.dart:547`.
RFC 6902 §4.6: objects are equal when they contain the same members
regardless of order; numbers when numerically equal. P5: `test` of
`{"x":1,"y":2}` against `{"y":2,"x":1}` fails; `1` against `1.0` fails. A
client guarding a patch with `test` is refused for a document it holds
correctly. Change: a structural deep-equals.

**9. 🟡 `$reindex` answers `Content-Location:
http://host/?$reindex-status`.** `reindex_handler.dart:815-819`:
`requestedUri.replace(path: '/', query: '')` keeps an empty query, so the
URL has `?` before `$reindex-status` and names the system search. P6.
Change: `Uri(scheme, host, port, path: r'/$reindex-status')`.

**10. 🟡 `$expand` with a Parameters body whose `offset`/`count` are
`valueInteger` is a 500.** `terminology_handler.dart:356-359` casts
`params['offset'] as String?`; `parametersToMap` hands the integer
through. P8: Parameters `valueInteger` → 500 `Internal error`; the query
string and `valueString` forms → 200. The OperationDefinition types both
as `integer`. Change: accept `int` or a numeric string.

**11. 🟡 A type-level `GET /[type]?…` search is audited as `read`.**
`audit_middleware.dart:_mapSubtype` says `read` for every GET without a
`_search` segment. P9: `GET /Patient?name=x` → subtype `read`, `POST
/Patient/_search` → `search`, `GET /Patient/nope` → `read`. The trail
cannot tell a search of a type from a read of one record. Change: a
one-segment GET whose segment is a resource type is `search-type` (the
restful-interaction code), as the Bundle-entry path already decides.

**12. 🟡 Stores created before 2026-09-18 never receive
`fhirant-operations.ndjson`.** `spec_loader.dart:534-537` skips the whole
load when any CodeSystem is held. P10: a store holding one CodeSystem,
given a directory with a new OperationDefinition file → 0 loaded; the
file has 4 definitions (added `f026fce`, 2026-09-18, for C3). On such a
store the CapabilityStatement cites four canonicals the server does not
hold, which is what C3 fixed. Change: skip per file (a per-file marker, or
"load what `heldKeys` says is missing" for every file, which the loader
already does per chunk and is cheap once the files are read).

**13. 🟡 `POST /auth/register` with a non-string scope entry is a 500.**
`register_handler.dart:898` `rawScopes.cast<String>()` throws inside the
catch. P14: `scopes: [42]` → 500 `Registration failed`. `account_rules.dart
scopesError` already answers this case; registration does not use it.

**14. 🟡 CQL translation runs on the server isolate, outside the program
deadline.** `cql_handler.dart _parseCql` → `libraryFromCql`. P13: 15 KB
of CQL translates in 915 ms, 65 KB in 1,478 ms, 269 KB in 5,343 ms,
linear; the body cap is 16 MiB. A caller with `$cql` rights holds every
other request for the duration (A9 moved execution, not translation).
FHIRPath parsing is not the same shape: 1,000 terms in 30 ms, 10,000 terms
a StackOverflowError at 104 ms, which the handler's `catch (e)` answers as
400. Change: translate inside `runProgram` too (the source crosses as a
string, the ELM comes back as JSON).

**15. 🟡 The rate limiter's `MemStorage` never removes a key.** By
reading `shelf_rate_limiter` 1.0.1 `memory_storage.dart`: `add` creates
an `IpItem` per address, `resetAll`/`resetIp` reset counts, nothing
evicts. One entry per distinct client address for the life of the
process, for both limiters. On a LAN that is a handful; on an address
the internet can reach it is unbounded. Unmeasured; a few hundred bytes
per entry. Change: a storage that drops entries whose window has passed
(the package's `BaseStorage` is eleven methods).

## No finding (probed, and reported so it is not re-raised)

- `fhir_db search(count: null)` returns every match (`_pagedIds` adds no
  LIMIT), so the forecast's Immunization load, CQL's `_loadPatientData`
  and the subscription sweep read the whole set.
- Id lists reach SQL through `json_each` (`_idsIn`) and 500-id chunks
  (`exportJson`, `heldKeys`): no bound-variable limit.
- `locked_until`, `expires_at`, `completed_at` are epoch seconds from
  `millisecondsSinceEpoch`: no local/UTC mismatch.
- `_filter=not(status eq final)` over 5,000 Observations: 128 ms
  (P15); `status eq preliminary` 30 ms, plain `status=` 18 ms.
- `$validate` never calls `getResourceNames` (P12: 0 calls over three
  validations with the specification loaded, 32-178 ms each); neither
  `fhir_r4_validation` nor `fhir_r4_mapping` invokes FHIRPath type
  checking, the only caller. One call would cost 2.5 s (1,745 names).
- The credential limiter is not bypassed by a trailing slash, a doubled
  inner slash or percent-encoding (all 404 at the router, P2).
- `SubscriptionService.onResourceChanged` never throws, so the PATCH
  handler's catch around it cannot turn a saved patch into a 400.
- `$document` includes every resource the Composition references directly;
  documents.html (read 2026-10-06): indirect references "may also be
  included", so the non-recursive build conforms.
- The compose file refuses an unset or empty key (`${VAR:?}`); only the
  bare CLI has finding 2.
